My recommendation

What I'd ship as the default, and my honest read on the feature.

Breadcrumb: go with #2 “Light band” or #5 “Eyebrow + title”recommended

#2 is the safe, familiar choice — a quiet full-width band under the menu that orients without shouting. It matches the app's existing light surfaces and never competes with page headings.

#5 is stronger: it folds the page's H1 into the breadcrumb, so you reclaim vertical space and every page gets a consistent title treatment. Pick this if you want the breadcrumb to also be the page header.

Skip #3 (accent card) for everyday use — it's eye-catching but heavy on every page. #1 is almost invisible; #4's chip is nice but the icons add clutter.

Dockable menu: default to Top, pinnedrecommended default

Top-pinned is what users already have and expect — zero learning curve, nothing hides, works on every screen size. Offer Left as the opt-in power-user layout (great when the nav grows), and Right for left-handed / dual-monitor setups.

My honest take: auto-hide is the risky part. Timed hiding (the 2s) frustrates people who lose the menu mid-thought; the industry trend (VS Code, Slack, Teams) is a manual collapse plus edge-reveal, not a timer. I'd ship the dock + pin, make edge-hover reveal the behaviour when unpinned, and treat the 2s auto-hide as optional — off by default.

Net: a genuinely nice power-user feature, low risk if top-pinned stays the default and auto-hide is opt-in.

Where preferences live

Position + pin + auto-hide would save per user (a small addition to user settings), so the “set as default” icon persists across sign-ins and devices. Until a user sets one, everyone gets Top, pinned.
