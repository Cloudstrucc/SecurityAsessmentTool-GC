    Saved
    Why this beats editing raw text: today the provider has to find ~60 [[VALUE:]] markers across five controls and overwrite each one by hand, and the app has no way to tell a filled draft from an untouched one — so progress reads “0 of 5 · 0%” even when all five drafts exist. Slots make completeness measurable, and they give the assessor a structured record of exactly which fact came from where.

    How it behaves

    • Click a slot → a modal. Value slots open a small rich-text box (bold, italic, lists, tables pasted from a spreadsheet survive). Attachment slots open a drop zone.
    • Filled = green, with a ✓ and a preview of what you entered. Click again to read or edit; the modal keeps the original AI prompt (“location/name of audit event catalogue”) as the label so context is never lost.
    • Evidence view renders the finished narrative: values appear inline as normal prose, attachments as hyperlinks. Anything still empty shows red, so the reader can see the holes.
    • Add and remove slots. Select text and press + Value slot to turn it into one, or hover a slot and press × to drop it back to plain text. Providers can add an attachment slot where the AI did not ask for one.
    • Completeness drives everything. Mark ready stays disabled until the count hits 100%; the assessor’s dashboard shows “49 of 60 values, 8 of 14 files” instead of a binary.
    • Assessor side (not shown): each slot carries who filled it and when, and the audit view can flag a control whose evidence is mostly self-attested text with no attachments.
